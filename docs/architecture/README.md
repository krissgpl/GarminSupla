# Architecture Decision Records (ADR)

This directory contains Architecture Decision Records (ADRs) for the GarminSupla project.

ADRs document significant architectural decisions made during the project's development, including the context, rationale, and consequences of each decision.

## Purpose

Each ADR should answer the following questions:

- What problem was being solved?
- What options were considered?
- What decision was made?
- Why was this decision chosen?
- What are the consequences?

## Status

An ADR can have one of the following statuses:

- **Proposed** – The decision has been proposed but not yet accepted.
- **Accepted** – The decision has been approved and is in use.
- **Superseded** – The decision has been replaced by a newer ADR.

## Naming Convention

ADR files use sequential numbering:

```text
0001-title.md
0002-title.md
0003-title.md
```

Numbers are never reused or renumbered.

## Guidelines

- One architectural decision per ADR.
- Keep ADRs concise and focused.
- Record the reasoning behind the decision, not just the outcome.
- Once an ADR is accepted, it should not be modified except for minor corrections. New decisions should be documented in new ADRs.
